- The MetaTrader5 package is imported only in vps/mt5_bridge/native.py (read-only) and vps/mt5_exec/native_exec.py (Stage 10 demo execution), behind a whitelist proxy; the adapter connects to a pre-authenticated terminal and takes no account identity or secrets. Why: native read-only boundary stays isolated from the TypeScript app and from execution.
- The VPS gateway (vps/mt5_gateway) is a stdlib-only, loopback-bound HTTP/WS transport with a static typed route table over ReadOnlyMT5Adapter; no generic dispatch and no native access. Why: network reachability must never grant execution authority.
- Demo execution (vps/mt5_exec) is a separate loopback-only, token-protected process whose service re-validates on every call that the terminal account is DEMO and its login/server are whitelisted, refuses duplicate signal_ids, has no modify route, and its only close route (POST /v1/demo/close) closes a single position whose magic and comment match the bot signal_id, reporting UNVERIFIED unless re-read proves it gone. Why: execution capability exists only for a bound demo identity and never widens the read-only bridge.
- The market-data proxy (vps/md_proxy) is a stdlib-only, loopback-bound static allowlist (GET health, latest tick, symbol spec, M5/M15/H1/H4 pos-mode bars; XAUUSD/BTCUSD only) that rebuilds upstream paths, forwards no client headers, caps size/timeout, never follows redirects, and by default requires a Cloudflare Access JWT verified cryptographically (RS256 vs team JWKS, issuer, audience, exp/nbf; md_proxy/access.py). Why: the browser dashboard may read quotes/candles without exposing the gateway, account data or the execution service.
