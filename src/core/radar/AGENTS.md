- Market intelligence (src/core/intelligence, mtf-intel-v2) is a pure H4→H1→M15→M5→quality layer called by RadarRuntimeService and attached as optional snapshot.intelligence; its confidence and READY are descriptive context only and never feed signal/plan/paper. Why: context ≠ decision.
- Radar read model (src/core/radar) is composed only inside MarketRuntime: one RadarRuntimeService per runtime, fed by the M5 aggregator's CLOSED emissions after CandleStore append; it reuses the existing M1B.3/5/6/8/9/10/11 engines, owns only its event-engine state, never imports signal/plan/risk/execution, and exposes a deep-frozen radar-v1 snapshot with no score/confidence fields. Validation mode is REAL only for BROKER_REPORTED specs. Radar evidence merges broker CLOSED history (older than the first live closed bar) with live CLOSED bars and bootstraps once on the latest history M5. Why: dashboard awareness ≠ decision, and per-symbol runtimes must never share state.
- Live paper loop (src/core/paper/LivePaperLoop.ts) is composed only inside MarketRuntime next to the radar: CLOSED M5 → existing M1B.3–7 → M2 → M3 → M4 → M5 paper → M6 journal, fills from the latest LIVE bid/ask, exits on later CLOSED bars, virtual account per runtime; never imports broker/gateway. Every journal row and radar snapshot carries a DataSource (REAL_MT5 only for BROKER_REPORTED specs). Why: real-market validation without an order path or mixed-source statistics.
- Decision Gate (src/core/paper/decisionGate.ts, DECISION_GATE_POLICY_VERSION) is the single entry authority in LivePaperLoop: an M1B READY is only a request and opens only when ARENA operator.status (copied from the same evaluateAt as primary_bias) is CARI_BUY/CARI_SELL on the same side; HOLD, missing, unknown or failed status blocks (BLOCK_ARENA_HOLD/BLOCK_ARENA_INVALID/BLOCK_DIRECTION_MISMATCH). Demo receives only gated opens. The loop keeps a copy-only CANDIDATE/GATE/ORDER/CLOSE decision log, and journal rows carry a frozen entryDecision snapshot. Why: one judge for paper and demo entries, with traceable reasons and no new formulas.
- Aligned backtest (src/core/paper/alignedReplay.ts, ALIGNED_REPLAY_VERSION) drives the SAME LivePaperLoop over native broker CLOSED M5/M15/H1/H4 bars (never aggregated; any missing timeframe ⇒ DATA_MISSING, no fallback) with a primaryBias provider calling the SAME ARENA evaluate() as TechnicalSliceService.evaluateAt; quote/spread/asOf differences are listed in ALIGNED_REPLAY_KNOWN_GAPS. M7 stress-test stays a synthetic robustness runner. Why: backtest must judge the real paper/demo path, not a second pipeline.
